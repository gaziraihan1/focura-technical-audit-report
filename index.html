Executive Summary

Focura is a full-stack SaaS project management platform built by a solo developer. It spans two repositories: a Next.js 16 / React 19 frontend and an Express.js / TypeScript backend, connected via RS256 JWT authentication, Prisma/PostgreSQL, Upstash Redis, and SSE-based real-time notifications.

Overall, Focura demonstrates a production-grade architecture for a solo-built SaaS. The modular monolith backend, asymmetric JWT design, and disciplined hook-first frontend pattern are significantly above average for projects at this stage. Primary improvement areas are test coverage depth, CI/CD automation, and security hardening.

Architecture & Structure
9 / 10

Focura follows a clean separation of concerns: a Next.js App Router frontend and an Express.js modular monolith backend. The frontend uses a layered convention: types.ts → constants/ → hooks/ → components/ui/ → components/sections/ → barrel index.ts → page orchestrator. The backend enforces per-module file conventions keeping every domain fully self-contained.

Strengths
Improvements
  • Strict module boundaries on both frontend and backend
  • Hook-first data layer: 80+ hooks, zero logic in UI components
  • queryKeys factories for predictable cache invalidation
  • resolveWorkspaceId middleware centralises workspace param resolution
  • No hidden magic: explicit imports, explicit middleware, explicit error flow

MediumHealth checkAdd GET /health and GET /ready endpoints for load balancers and uptime monitors.

Security
8 / 10

The RS256 asymmetric JWT implementation is a standout security decision. Private key never leaves the backend, access tokens expire in 15 minutes, refresh tokens rotate on use (7-day lifetime), and JTIs are tracked in Redis for instant revocation. Argon2 is used for password hashing.

Strengths
Security Issues
  • RS256 asymmetric JWT — private key never exposed to frontend
  • HTTP-only cookies prevent XSS token theft
  • Refresh token rotation with JTI revocation via Redis
  • Global invalidation via token version increment
  • Argon2 password hashing (gold standard)
  • Audit logging for all security-relevant events
  • Workspace-scoped data isolation prevents cross-tenant leakage
SeverityIssueRecommended Fix
HighRSA private key committed riskConfirm private.pem is correctly gitignored and never committed. Add secret-scanning CI step.
HighSSE token in query paramGET /notifications/stream?token=… exposes access token in logs. Prefer short-lived signed stream tokens or cookie-based SSE auth.
MediumCORS configurationEnsure wildcard origins are not permitted in production. Validate OPTIONS preflight headers.
MediumInput sanitizationZod validates shape but ensure all string fields sanitize HTML to prevent stored XSS.
MediumHelmet.jsConfirm express-helmet is used to set security headers (X-Frame-Options, CSP, HSTS, etc.).
LowFile upload type validationEnsure uploaded files are validated by MIME type and magic bytes — not just extension.

Performance & Scalability
7 / 10

Optimistic updates make mutations feel instant. TanStack Query handles deduplication and stale-while-revalidate caching. SSE is an appropriate choice for real-time in a Node.js monolith but has scaling implications.

PriorityAreaRecommendation
HighSSE scalabilityIn-memory SSE connections break with horizontal scaling. Use Redis Pub/Sub to fan out events across instances.
HighDB connection poolingConfirm connection string uses PgBouncer pooler endpoint for read-heavy queries.
MediumQuery optimisationEnable Prisma query logging to identify slow queries. Add composite indexes for high-frequency filters.
MediumResponse cachingAdd Redis caching with 60s TTL for analytics and statistics endpoints.
LowBundle sizeAudit frontend bundle with next build --analyze. Framer Motion, Recharts, Redux Toolkit add weight.

API Design
8 / 10

The API largely follows REST conventions: plural noun resources, correct HTTP verbs, workspace context in URL path. Responses use a consistent { success, data, message } envelope. Paginated responses add meta which diverges from the base ApiResponse shape — root cause of type mismatch issues.

PriorityAreaRecommendation
HighPaginated response typeDefine PaginatedApiResponse<T> = { success, data: T[], meta: { total, page, limit, totalPages } } everywhere.
MediumAPI versioningPrefix all routes with /api/v1/ now, before the API is public.
MediumOpenAPI documentationUse tsoa or zod-to-openapi to auto-generate an OpenAPI spec from route definitions.
LowHATEOAS linksConsider including _links in responses to make the API self-documenting.

Real-Time Architecture (SSE)
8 / 10

SSE is the correct choice for unidirectional notification push in a Node.js monolith. JWT is verified on connection (userId always from token, never URL param). Supports four dispatch patterns: single user, task assignees, workspace members, and @mentions.

PriorityAreaRecommendation
HighToken in query paramMove stream auth to a short-lived signed stream token or cookie to avoid exposing access tokens in logs.
HighMulti-instance SSEIn-memory connections break with horizontal scaling. Implement Redis Pub/Sub to fan out across instances.
MediumReconnection handlingAdd exponential backoff reconnection logic and Last-Event-ID support for event replay.

Prisma ORM with PostgreSQL (Supabase). All queries filtered by workspaceId preventing cross-tenant leaks. Reusable select objects in .selects.ts files. Clean migration discipline demonstrated by BillingEvent providerEventId migration.

Final Summary & Conclusion

Focura is an impressive solo-built SaaS platform demonstrating professional-grade architectural thinking. The RS256 JWT, modular monolith, hook-first frontend, and comprehensive documentation all reflect a developer operating well above the typical solo-project standard.

The most significant gaps are testing coverage, CI/CD automation, and observability. Addressing Critical and High priority items would bring the overall score from:

7.8 → ~9.0
Grade: B+ → A with Critical/High fixes applied
